# Private real-coordinator SDR recipe preparation

Base: repository `.github/scripts/hero-coordinator-app-probe`. Assemble AppKit/SwiftUI imports + `ProductHero.swift` + `FlightSDR.swift.inc` + `Driver.swift.inc`, with the **unchanged** separate ProductImage/Style/Dependencies and run-one wrapper. The immutable Hero/Driver inputs are in `base/`; all input hashes are recorded. This requires the new-SDK real clock build used by the original app-loop cohort. Do not add SDK14 static-clock fatal guards, actor shims or alternate timers. No compile/UI/CI was performed here.

`BERN_HERO_FLIGHT_SDR=default|baked-pair` is process-cached (unset default); invalid fails before window creation. OS14 accepts default only; OS13 accepts either. Binary CLI remains `binary namedAsset output`; the old wrapper remains four arguments `binary namedAsset output expectedOS`. The exact opaque/up named asset, Scene's explicit Standard intent, source/destination `.id`, key, geometry and corner remain original. This is not product intent routing: Runtime→Style→Probe still does not pass dynamicRange.

Each real image snapshot begins a distinct ordinal record before its existing guards and reads its actual renderer.cgImage **once**. Default observes scalar layout and retains only a CGColorSpace reference plus weak anchor/display NSImage references; it constructs no CI/output and never retains the original CGImage. Candidate applies the prior fixed recipe independently to the actual two snapshots: one shared CIContext, each actual original CGImage→CIImage(true, no input-space override)→exact-extent RGBA8/sRGB `deferred:false`, then the original-size NSImage wrapper. It caches exactly two derived images; it does not merge same-key calls or cache by a potentially reused CG address. Unknown geometry/layout, any incomplete/extra primary attempt, CI failure or wrapper/mapping failure is sticky; there is no successful original-image fallback in candidate acquisition. The default recipe must be validated before candidate execution.

Driver's existing scalar observer records `started_uptime`, `from_nsimage_id`, `to_nsimage_id` and matches actual Flight.from/to against the weak wrappers. It never creates or retains a flight; repeated samples recheck the single identity/mapping. Original Hero code outside snapshot—including timer/tick/visibility/draw/finish—is byte-identical. Original Scene, sampler callback, arm/next-sample block, NSApplication.run/stop/wake, time/sample limits and native/cache/normal/front/noMTK/capture contracts remain. Additional helper errors are checked before sampling proceeds and at final validation; finalization failure forces nonzero exit.

- `records[]`: `ordinal`, `key`, `anchor_identity`, `snapshot_started_uptime`, `renderer_returned_uptime`, `conversion_started_uptime`, `conversion_finished_uptime`, `nsimage_wrapped_uptime`, `snapshot_returning_uptime`, `wrapped`, `rect_in_overlay`, `logical_size`, `input_object_id`, `input_layout`, `input_extent`, `input_color_space`, `display_nsimage_id`, `flight_role`. Candidate adds derived identity/layout/color-space, requested true/**actual tone-map application unknown**, fixed requested format/space and deferred=false. Default conversion times are null. Failed records retain actual available fields and error; records are never deduplicated to manufacture two.
- `flight_mapping`: actual flight identity, `flight_started_uptime`, `first_live_observation_uptime`, `transition_uptime`, `from_ordinal`/`to_ordinal`, actual from/to NSImage IDs. These timestamps permit latency analysis; first observer sample is not first rendered frame.
- `helper_references_cleared`, `release_scope`, `helper_retained_original_cgimage_count=0`, `helper_original_provider_read_count=0`. These last counters describe only this helper, not the unchanged cache ledger or WindowServer capture.

Original cleanup first freezes acquisition. Any cleanup snapshot passes through original pixels without conversion, new scalar observation or binding. After the original window teardown, finish serializes input CGColorSpace and derived layout/ICC metadata, clears helper cache/context/space/weak references and reports partial failure if acquisition or two-output/one-context contracts failed. This claims helper-reference cleanup only, not global deallocation or zero observer effect. Original raw snapshot pixels are neither exported nor copied by this helper.

Static recipe mixed improvements/regressions, High/other inputs and full product intent/lifecycle remain unverified. This preparation does not adopt the recipe.

# 下一条单一边界：实际 snapshot 的 CG direct 适配

本轮只形成下一检查点，不写 helper/driver/产品，不构建、UI、CI 或新像素算法。CI40119614788 的现有小汇总确认两个 host、两个 key 均为 intent=0、isMask=false、shouldInterpolate=true、decode=nil；root 已报告四组 old-float→off／off→on 的全部12ROI raw+sRGB exact，四个 raw SHA 与旧 cohort exact。结论只排除这些已观察状态的差异，未定位显示残差来源。

**唯一候选**是在原静态 Flight 的现有 CGContext 中直接画同一次 renderer-return CGImage，与原 NSImage.draw 默认路径配对。首轮只对 named、opaque、orientation up、相同宽高比、corner=0、p=0/1；custom 继续原路径。先做13同机 default/direct 配对，以冻结的14实际 Hero 默认结果为固定比较目标，不另加显示控件、缓存、图层或 context 配置变体。SDK14.2 NSImage.h:190–198 说明从 CGImage 初始化所得图像的绘制等价；因此这是可证伪的 adapter 边界，不能预言会改善，也不能把有差异直接归因于 NSImage。

对象控制须在同一原 snapshot hook 取得原 `pixels`，仍照常构造原 NSImage；禁止从 NSImage.cgImage/TIFF 再取、代入原源、重复 renderer、复制/重标记/转换图像或为显示增加 provider 访问。default 与 direct 都复用原 float-on 的同一持有容器、两个唯一 primary key、对象数与释放时点；default 同样完成关联但只用原 NSImage.draw。named Flight 的 from/to 仍是同一 NSImage，并明确关联到该 key 的同一原 CGImage；关联缺失或重复即 incomplete，不回退取另一张图。两模式均沿用原 post-PNG+teardown 导出与释放；原 float-off 语义不变。新共享 retention 的 default 必须先重现旧 on 的12ROI、raw SHA 与生命周期控制，不能将不同 retention 的 off 直接当作唯一对照。

绘制只替换 named 的两条 image-draw 原语：沿用当前 view/context、现有 clip、bounds、backing scale、显示与捕获流程；不建 bitmap context、不改变 logical 320×180 或13/14实际2×/1× payload尺寸。保持原顺序：from 的 sourceOver/fraction=1，再 to 的 sourceOver/fraction=clamp(p)。CG 路径固定采用 normal source-over 与对应 global alpha，两次都画原图到完整相同 bounds；不做手动 premultiply/unpremultiply、alpha改写、copy blend 或 p=1 单次优化。[Apple Quartz 文档](https://developer.apple.com/library/archive/documentation/GraphicsImaging/Conceptual/drawingwithquartz2d/dq_images/dq_images.html)说明 normal 的 source-over 行为及 alpha=1 的覆盖语义；此步仅验证 opaque 端点，不能外推半透明混合。

坐标必须从现有 `isFlipped=true` 推导，不能按颜色好看与否选正反。原 NSImage 路径保留 respectFlipped=true；CG 路径在局部 save/restore 内、保持原 CTM 的尺度与位置，仅作一次绕同 bounds 的 y 反转（本夹具零原点 bounds：先平移 height，再 y scale=-1），不额外做 backing-scale 或 image-pixel 缩放。[Apple flip 说明](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/CocoaDrawingGuide/Transforms/Transforms.html)支持这种局部方向补偿。实施前 source review 核两次 alpha/blend/clip 与成对 state restore；运行判读先要求 atlas 三行、上下不对称结构及 ramp 方位正确、非空、完整同 extent，无空白/背景泄漏，p0/p1 均通过。倒图、错位、裁切、空图、缺字段或 sourceOver 状态不明一律 incomplete，不能凭色差更小称改善，也不搜索翻转/alpha 变体。

像素目标固定为每个原 ROI 的 `D13 − D14`，其中 `Dh = Hero_h − body_h`；候选用 `D13_direct − D14_default`，同时保留 `D13_default − D14_default`。使用冻结的几何/ROI与既有 raw+sRGB读法，完整报告 named 十块与 ramp、p0/p1 的有符号各通道残差、绝对汇总及所有退步项；custom/其它控制也须原样通过。不能挑一块亮色，不能将 Hero13=body13 或 bodyexact 当目标；14实际 Hero 本身已有非零 D14。default重现、native/front/normal/cache、非空几何、PNG完成与普通partial/no-overwrite 任一失败即停止颜色结论；保留失败状态，不能静默切回默认后标为 direct 成功。原 hard watchdog 与错误退出边界保持。

即使 direct 更接近14，本步最多表明该夹具的适配路线敏感性；若无改善则记录阴性，不继续 widget 变体。本轮不验证其它方向、alpha、fit、圆角、实际协调动画、High/HLG 或普遍 HDR；不提出文件 SHA 白名单、RGB 补偿、自创 tonemap 或 layer setter。

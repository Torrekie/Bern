# Private static root/actual-overlay route candidate

Prepared only; not compiled, launched, published, or applied to the repository. Root decides whether to build/run after reviewing the remote backing observations. Existing layer hints are not treated as actual storage or a cause.

`provenance.json` locks the base `work/native-pq-hero-backing-observer/Driver.swift.inc`. `static-route-driver.patch` transforms only that driver; `StaticRoute.swift.inc` is placed immediately before the patched driver in the same combined file as the unchanged actual hero and float helper. Local SDK guards remain the base fixture's guards. No base source is copied or overwritten here. The resulting driver hashes (with/without helper) are recorded for root's assembly.

`BERN_HERO_STATIC_ROUTE` is process-cached: unset/root preserves direct FixtureRoot parenting; overlay mounts each exact same manual Flight under `manager.fixtureExistingOverlay`, which snapshot already prepared. Invalid mode, backing observation selected anything except off, or float capture selected anything except off fails before window creation. This prevents mixing route selection with the two existing experiments.

The sole mount difference is `frame = overlay.convert(D, from: root)` and adding to the existing overlay. Both paths use the same images, draw method, corner, progress, fixed desired bottom-row D rectangles and existing screenshot ROI calculation. Direct retained-flight checks immediately after mounting, on each original sampling iteration, and after PNG/final guards require the selected parent, same window,320×180bounds, D→parent→D error≤0.000001point and no MTKView in either flight subtree. That explicitly covers overlay siblings omitted by the original root-descendants walk; original root/manager/no-clock/stable5/cache/normal/front/deadline gates stay intact.

New scalar report fields are `static_route`, `static_route_mount` and `static_route_post_png`; the latter lists desired-root, parent-local and back-converted-root rectangles plus actual maximum error, selected-parent identity and subtree no-Metal count per source role. No contents, provider, presentation layer, backing-layer property or image is read by the helper.

Only overlay-mode views created by this fixture are kept for teardown removal. After the original orderOut, they are removed and that fixture list cleared before original contentView clearing/close/watchdog cancellation. Root mode adds no owned-view retention. No manager enter/leave/finish, visibility callback, live binding, entry/departure/flight map, layer setter or overlay geometry change is added.

Source patch was forward-applied to a temporary private output and byte-reversed to the exact base; the temporary was removed. This is source verification, not Swift typechecking/runtime acceptance. The candidate only compares static endpoint routes. It does not validate the actual timer-driven flight, hiding/restoration, retargeting or physical HDR.
